# 팀원별 로봇 제어 개발

[README](../README.md) · [학습·제어기 연결](TRAINING.md) · [개발·테스트](DEVELOPMENT.md)

## 역할과 수정 범위

| 담당 | 관리할 내용 |
|---|---|
| 공통 환경 담당 | 관측·행동 형식, 물리·센서, 게임 판정·아이 행동, 시간 진행, 기록·평가 형식 |
| 게임별 로봇 담당 | 자신의 제어기, ML 모델·학습 코드·보상 함수, 모델 설정·의존 패키지 |
| 게임 규칙 변경 담당 | 변경 사유·규칙·테스트를 제안하고 공통 환경 담당자와 합의해 반영 |

모델을 비교할 때는 아이 행동이나 물리값을 각자 수정하지 않습니다. 변경이 필요하면 별도 변경으로 검토하고 새 환경 버전을 사용합니다. 게임별 성과는 같은 게임의 기준 제어기와 비교하고, 근접·급회전·막힌 이동 같은 공통 지표도 함께 확인합니다.

## 각자 시작하기

1. 관리자가 정한 같은 커밋 또는 태그의 저장소를 각자 받습니다. 실행 방법은 README를 따릅니다.
2. 각자의 컴퓨터·프로세스에서 실행합니다. 하나의 서버를 여러 제어기가 동시에 조작하지 않습니다.
3. ML 패키지는 자신의 가상환경에 설치합니다. 기본 시뮬레이터 실행에는 추가 패키지가 필요하지 않습니다.
4. [제어기 예제](../simulator/examples/controller_client.py)를 실행한 뒤 자신의 제어기로 교체합니다.
5. 학습에 쓰지 않은 평가 상황에서 기준 제어기와 같은 조건으로 비교합니다.

제어기는 `reset(seed=None)`으로 한 판의 내부 상태를 초기화하고 `predict(observation)`으로 행동을 반환합니다. 출력은 `MotionAction` 또는 `linear_mps`·`angular_rps`와 선택적 `guard`를 가진 객체입니다. 좌표계·단위·가변 인원 마스크·관측 출처는 [공통 계약](TRAINING.md)을 따릅니다. `oracle` 관측을 사용하는 실험과 카메라·센서 실험은 구분해서 보고합니다.

## 변경 공유하기

Git을 사용하면 담당 기능별 브랜치에서 작업하고 변경 요청(PR)으로 합칩니다. 제어기 수정과 공통 엔진 수정은 분리합니다. 공통 형식이나 게임 규칙을 바꾸는 PR에는 관련 테스트와 문서 변경을 포함합니다. 새 버전을 받으면 사용하던 서버를 재시작하고 제어기 연결 예제를 다시 확인합니다.

| 결과와 함께 남길 항목 | 목적 |
|---|---|
| 시뮬레이터 커밋·계약 버전·물리 설정 | 어떤 환경에서 실행했는지 식별 |
| 모델 버전·학습 설정·관측 모드 | 어떤 입력으로 무엇을 학습했는지 식별 |
| 게임·시나리오·시드·아이 수·제한 시간 | 같은 초기 조건으로 비교 |
| 평가 세트·기준 제어기·성과·공통 지표 | 변경 효과 확인 |

기록 파일 저장과 여러 판 데이터 생성은 선택해서 실행합니다. 대용량 출력·영상·모델 가중치는 기본 소스 변경에 함께 넣지 않고, 공유 위치와 해당 파일의 식별자를 결과에 남깁니다.

## 경찰과 도둑 및 새 게임 연결

경찰과 도둑은 현재 선택 목록의 비활성 **구현 예정** 항목입니다. 게임 로직과 로봇 모델은 해당 담당자가 구현하며, 동작하는 게임 등록 API가 이미 제공된 것으로 취급하지 않습니다. 다음 내용을 합의한 변경으로 연결합니다.

1. 모드 이름, 설정값, 역할과 게임 단계·종료 조건을 정의합니다.
2. 아이들의 상태 전환·반응과 잡힘·구조 등의 판정을 구현합니다.
3. 공통 관측·행동 형식을 유지하고 추가 정보가 필요하면 계약을 검토합니다.
4. 게임별 보상·성과 지표를 정하고 기존 공통 지표와 함께 평가합니다.
5. 상태 전환·종료·잘못된 입력·기존 게임 회귀 테스트를 추가한 뒤 화면 옵션과 문서를 활성화합니다.
